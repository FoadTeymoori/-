# 🔧 ورژن نرم‌افزارها و پروژه‌ها یعنی چی؟

🔹 احتمالاً موقع دانلود نرم‌افزار یا بررسی پروژه‌های گیت‌هاب، با شماره‌هایی مثل `v1.2.0` مواجه شدید. اما این اعداد دقیقاً چه معنایی دارن و حروفی مثل Alpha و Beta چی می‌گن؟ 🤔

## 🔹 ۱. ساختار شماره نسخه (Versioning)

یکی از روش‌های رایج شماره‌گذاری نسخه‌ها، **Semantic Versioning (SemVer)** هست:

`MAJOR.MINOR.PATCH`

مثلاً در نسخه `v1.2.0`:

🟢 **MAJOR (عدد اول)**

وقتی تغییرات بزرگ و ناسازگار با نسخه‌های قبلی ایجاد می‌شن، این عدد افزایش پیدا می‌کنه.

مثال: `v1.2.0` ← `v2.0.0`

🟠 **MINOR (عدد دوم)**

وقتی قابلیت‌های جدیدی اضافه می‌شن و همچنان سازگاری با نسخه‌های قبلی حفظ می‌شه، این عدد افزایش پیدا می‌کنه.

مثال: `v1.2.0` ← `v1.3.0`

🔴 **PATCH (عدد سوم)**

برای رفع باگ‌ها و اصلاحات کوچکی که با نسخه‌های قبلی سازگار هستن، استفاده می‌شه.

مثال: `v1.2.0` ← `v1.2.1`

⚠️ **یه نکته مهم:** این اعداد قرار نیست بعد از هر ۱۰ بار به عدد بعدی منتقل بشن! مثلاً بعد از `v1.2.9`، الزاماً نسخه `v1.3.0` منتشر نمی‌شه؛ ممکنه نسخه `v1.2.10` باشه. زمان تغییر هر بخش به نوع تغییرات پروژه بستگی داره.

## 🔹 ۲. Alpha، Beta و RC چی هستن؟

گاهی کنار شماره نسخه، عباراتی مثل Alpha یا Beta دیده می‌شه. این عبارات مرحله توسعه و آمادگی نرم‌افزار رو مشخص می‌کنن.

🔸 **Pre-Alpha:** پروژه هنوز در مراحل اولیه توسعه قرار داره و ممکنه بسیاری از قابلیت‌ها پیاده‌سازی نشده باشن.

🔸 **Alpha:** نسخه اولیه برای آزمایش و توسعه؛ ممکنه ناقص باشه و باگ‌های زیادی داشته باشه.

🔸 **Beta:** نسخه‌ای که معمولاً بخش عمده قابلیت‌هاش پیاده‌سازی شده و برای آزمایش گسترده‌تر منتشر می‌شه؛ اما هنوز ممکنه مشکلاتی داشته باشه.

🔸 **RC (Release Candidate):** نسخه‌ای که برای انتشار نهایی در نظر گرفته شده؛ اگر مشکل مهمی پیدا نشه، ممکنه همون نسخه به‌عنوان نسخه نهایی منتشر بشه.

🟢 **Stable:** نسخه پایدار که برای استفاده عمومی آماده شده؛ البته پایدار بودن به معنی بدون باگ بودن نیست!

## 🔹 ۳. ترتیب مراحل توسعه

یک مسیر رایج برای انتشار نرم‌افزار به این شکله:

`Pre-Alpha → Alpha → Beta → RC → Stable`

البته همه پروژه‌ها از تمام این مراحل استفاده نمی‌کنن و ممکنه ترتیب یا روش انتشارشون متفاوت باشه.

## 🔹 ۴. یه مثال کاربردی

فرض کنید یک پروژه متن‌باز در گیت‌هاب دارید:

- `v0.1.0-alpha` → نسخه اولیه در حال توسعه
- `v0.5.0-beta` → نسخه آزمایشی با قابلیت‌های بیشتر
- `v1.0.0` → اولین نسخه پایدار با شماره نسخه اصلی ۱
- `v1.1.0` → اضافه شدن قابلیت جدید و سازگار
- `v1.1.1` → رفع یک باگ
- `v2.0.0` → تغییرات ناسازگار با نسخه‌های قبلی

📌 **نکته:** در SemVer، نسخه‌های `0.x.x` معمولاً برای توسعه اولیه استفاده می‌شن و ممکنه تغییرات ناسازگار زیادی داشته باشن. همچنین Alpha و Beta صرفاً برچسب مرحله توسعه هستن و به‌تنهایی تضمین نمی‌کنن که نسخه حتماً چه امکانات یا چه تعداد باگی داره.

💬 حالا که با شماره نسخه‌ها آشنا شدید، دفعه بعد که وارد GitHub شدید، می‌تونید بهتر متوجه بشید هر پروژه در چه مرحله‌ای قرار داره و تغییرات نسخه‌های مختلفش چه معنایی دارن.
